# Login and administrator-managed access

The owner API requires an active user's opaque, HttpOnly session cookie. Unsafe authenticated requests also require the session's `X-CSRF-Token`. All private responses use `Cache-Control: no-store`. Public HTML contains no account data. The separate shared-map service retains its existing bearer capability contract.

There is no public registration or automatic SSO signup. A deployment command or one-time environment bootstrap creates the first administrator. Administrators can add/invite users, renew invitations, change roles and disable access in Settings. Invitation URLs carry a single-use, expiring random token in the fragment; only its hash is stored. Invitations are copied for delivery, not emailed automatically. Members share the existing garage; administration and share-link creation are admin-only.

Public owner endpoints: GET `/api/health`, GET `/api/auth/config` (setup and provider label only), GET `/api/auth/session` (401 when anonymous), POST `/api/auth/login`, POST `/api/auth/invitations/accept`, GET `/api/auth/oidc/start`, GET `/api/auth/oidc/callback`. All other owner API endpoints require authentication. Login/accept require same-origin JSON. Local-password/invitation sessions expire after eight hours by default (`PARKING_SESSION_HOURS`); SSO sessions expire after 30 days (`PARKING_SSO_SESSION_HOURS`). Both are absolute lifetimes, matched by the cookie's Max-Age, and are revoked on password change, role/access change and logout. Duration changes apply to new sessions only.

Authenticated endpoints: POST `/api/auth/logout`, POST `/api/auth/password`, GET `/api/admin/users`, POST `/api/admin/users`, PATCH `/api/admin/users/{id}`, POST `/api/admin/users/{id}/invite`, GET/PUT `/api/admin/sso`. Admin endpoints require an administrator. The last active administrator cannot be disabled or demoted.

SSO: one configurable OIDC provider, supporting Authentik and other standard providers. Discovery URL, exact issuer, client ID/secret and client authentication method come from environment or admin Settings. Authorization code + PKCE S256, browser-bound one-use state, nonce, signed ID token, issuer/audience/expiry validation. Only asymmetric signatures are accepted. An initial SSO identity may bind only to an existing allowed account with a verified matching email. Subsequent logins use issuer + subject; disabled users are rejected immediately. Tokens remain server-side and are discarded after login. HTTPS is required for remote provider/app URLs; loopback HTTP permits local testing. No SAML, LDAP, provider group-to-role mapping or global provider logout in this version.

Verification: anonymous/private route isolation; CSRF; session expiry/revocation; invitation single use/expiry/reissue; admin role/last-admin rules; secret redaction/encryption; first-admin bootstrap; mocked OIDC round trip including state/nonce/PKCE/issuer/audience/subject/admission checks; existing owner and shared-map regression suites.
