# SMTP ticket notifications

All email administration endpoints require an active administrator session; writes require same-origin JSON and X-CSRF-Token. Shared-map links never grant email/configuration access.

GET/PUT `/api/admin/email`: SMTP configuration (enabled, host, port, security=starttls|tls|none, username, optional replacement password, sender email/name, reply-to), new-ticket and monthly switches, report day 1–28/hour/minute in America/New_York. Password is write-only, encrypted at rest; an omitted/null replacement preserves it. Environment configuration can make SMTP read-only in Settings. Plain SMTP is limited to loopback test servers. Remote SMTP always verifies TLS. Default disabled until deliberately configured. Config responses also contain delivery counts, recent status records and missing-recipient count.

POST `/api/admin/email/test`: `{recipient}` queues one test email to the explicitly selected address. GET `/api/admin/email/preview?kind=new_ticket|monthly` returns a sample HTML email with synthetic data. POST `/api/admin/email/deliveries/{id}/retry`: retries failed messages; an uncertain SMTP handoff additionally requires `{acknowledge_uncertain:true}`.

For future collector discoveries, one durable outbox record per newly inserted ticket goes to that car's valid email. Ticket and outbox insert commit together. Repeated checks or ticket payment/status updates do not enqueue new alerts. Adding a vehicle's initial history, importing records, and enabling mail do not generate historical alert batches. Existing optional car-email editing controls recipients. Delivery checks the current recipient before sending; removed/changed addresses cancel old queued messages.

A periodic Celery task generates a single report batch per month once the configured time has passed, then drains the durable outbox. Missed current-month runs catch up when the app resumes; older unsent monthly reports are superseded. Reports group all current positive ticket balances by normalized recipient, across that person's vehicles (including paused vehicles). No outstanding balance => no report. Every item includes balance, issue date and elapsed calendar days, or an explicit unavailable/unverified age. Reports show the total outstanding balance, use current records at delivery time, and link to https://mvb.syr.gov/ via a Pay tickets button.

SMTP is disabled until configured. Safe failures retry with bounded backoff; confirmed permanent failures stop. Ambiguous disconnects during delivery and expired sending leases become uncertain, without automatic resend, because SMTP cannot guarantee exactly-once delivery after an interrupted handoff. Unique event keys, stable Message-ID values, transactionally queued events and guarded claims prevent routine duplicates. Sent means SMTP accepted the message, not confirmed inbox delivery. Errors and public status never contain credentials, raw server responses, or email bodies.

Verification uses isolated databases, a local SMTP capture server, synthetic recipients and MIME parsing; no real recipient is emailed during development. Check TLS requirements, new-ticket deduplication, monthly eligibility/grouping/age/totals, paid/missing-address exclusions, durable retry/cancellation, ambiguous handoff behavior, secret redaction, authorization and HTML escaping.
